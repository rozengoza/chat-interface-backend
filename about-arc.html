// auth flow
How It Works
01
Client sends credentials
POST /auth/login with username + password (bcrypt) or Bearer RS256 token from Neon Auth.
02
JWT issued or validated
Local mode signs a HS256 token. Neon Auth mode validates against the JWKS endpoint, extracting user_id.
03
Rate limit checked
Middleware verifies per-user daily quota against rate_limit_log before forwarding to AI provider.
04
Completion streamed
Backend proxies the request with the user's API key (in-memory only) and pipes SSE chunks to the frontend.
05
Message persisted
Full message pair saved to Neon PostgreSQL after stream ends. Context survives page reloads.

Local Dev Setup
# 1 · clone & install
$ git clone https://github.com/rozengoza/chat-interface-backend
$ cd chat-interface-backend && npm install

# 2 · configure
$ cp .env.example .env
DATABASE_URL=postgresql://...
JWT_SECRET=your-secret

# 3 · run schema in Neon SQL Editor, then:
$ npm run dev
